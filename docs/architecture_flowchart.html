1. ARSITEKTUR GLOBAL EKOSISTEM: APOGEE MASTER, PARTNER DEDICATED & OPEN API H2H

Bagaimana 1 Web Portal APOGEE Melayani Banyak Partner Dedicated (Partner A, B, C) & Klien Open API (A, B) Secara Terisolasi

Halaman 1 / 4 • Topologi Sistem APOGEE

🏢 1. APOGEE Master Server (Pusat)

  • Memegang otoritas lisensi (whitelabel_licenses), kredensial Open API, dan katalog induk APOGEE.
  • Menjadi Supplier H2H (Vendor APOGEE) ketika Partner Dedicated mengambil produk dari Master.
  • Memotong Saldo APOGEE milik Partner saat Partner mengirim transaksi ke Master.

🖥️ 2. Partner Dedicated (Partner A, B, C)

  • Login melalui portal web APOGEE Partner Console.
  • Memiliki Domain sendiri (mitrapulsa.my.id), IP VPS sendiri, & DB Supabase sendiri.
  • Bebas mengambil produk dari APOGEE Master ATAU menghubungkan vendor H2H milik sendiri.

⚡ 3. Mitra Open API (Open API A, B)

  • Login dengan API Key & Secret Key (otomatis masuk ke /openapi-portal/*).
  • Tidak punya DB/VPS sendiri — 100% langsung membaca & bertransaksi di APOGEE Master Server.
  • Transaksi via curl / H2H tercatat sebagai channel B2 • OpenAPI di APOGEE Master.

3. FLOWCHART 3 JALUR TRANSAKSI & CALLBACK OTOMATIS (END-TO-END)

Perbedaan Alur Saat Partner Order ke APOGEE Master vs Partner Order ke Vendor Sendiri vs Open API H2H Order ke APOGEE Master

Halaman 3 / 4 • Siklus Transaksi & Callback

🏷️ Aturan Tampilan Kode Transaksi & Ref ID

  • Di Partner Admin (Channel i1 • Apps): Hanya menampilkan Kode Transaksi tunggal (tanpa Ref: di bawahnya, dan tanpa menampilkan URL endpoint vendor internal).
  • Di APOGEE Master Superadmin (Channel B2 • OpenAPI & B2C • Partner): Menampilkan Kode Transaksi Master beserta Ref: <Kode_Partner> dan tombol Resend Callback.

🛡️ Proteksi Saldo Vendor & Status Produk

  • Jika transaksi gagal karena Saldo APOGEE Master di Vendor kurang (isVendorBalanceIssue), produk TIDAK dinonaktifkan (tetap aktif agar ketika deposit vendor diisi langsung bisa transaksi).
  • Jika transaksi timeout jaringan (indeterminate), status ditahan sebagai PROCESSING (Timeout is Pending, Never Failed) demi mencegah rugi refund ganda.
